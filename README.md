# DATUM Practice

DATUM Practice - веб-приложение для публикации информации о проектах DATUM Soft и ведения внутренней базы знаний. В системе есть публичная витрина проектов, защищенный раздел для авторизованных пользователей, иерархия разделов, карточки материалов и загрузка медиафайлов.

## Возможности

- Просмотр публичной главной страницы и списка проектов.
- Создание, редактирование и публикация проектов.
- Хранение описаний проектов, главных изображений и геоданных в формате GeoJSON.
- Авторизация пользователей через JWT.
- Работа с защищенной базой знаний.
- Создание древовидной структуры разделов и подразделов.
- Создание карточек внутри разделов.
- Загрузка главного изображения карточки и дополнительных вложений.
- Автоматическое формирование slug-адресов из названий.
- Разделение опубликованных и неопубликованных материалов.
- Автоматическая очистка замененных и удаленных медиафайлов.

## Руководство пользователя

### Вход в систему

1. Откройте приложение в браузере.
2. Перейдите на страницу авторизации.
3. Введите логин и пароль.
4. После успешного входа станут доступны закрытые разделы: база знаний, создание проектов, создание разделов и карточек
\(администратор имеет доступ ко всем материалам и может их удалять/редактироввать).

Публичные страницы проектов доступны без авторизации. Управление контентом доступно только авторизованному пользователю.

### Работа с проектами

Раздел `Проекты` используется для публикации информации о проектах компании.

**Опубликовать новый проект может только администратор**.

В проекте можно хранить:

- название;
- краткое описание;
- полное описание;
- главное изображение;
- GeoJSON-данные для отображения объекта на карте;
- статус публикации.

Чтобы добавить проект:

1. Войдите в систему.
2. Перейдите в `Проекты`.
3. Нажмите кнопку создания проекта.
4. Заполните обязательные поля.
5. При необходимости загрузите изображение и добавьте GeoJSON.
6. Включите публикацию, если проект должен быть виден пользователям.
7. Сохраните изменения.

### Работа с разделами

Разделы используются для организации базы знаний. Разделы могут иметь древовидную структуру: у раздела может быть родительский раздел и дочерние подразделы.

Раздел может хранить в себе:

- название;
- описание;
- родительский раздел;
- дочерний раздел;
- вложенные карточки;
- статус публикации.

_Важное правило: опубликованный подраздел не может находиться внутри неопубликованного родительского раздела. Если снять публикацию с раздела, его дочерние разделы и карточки также становятся неопубликованными._

### Работа с карточками

Карточка - основная единица хранения материалов внутри базы знаний. Каждая карточка принадлежит одному разделу.

Карточка может хранить в себе:

- название;
- краткое описание;
- основной текст;
- главное изображение;
- дополнительные файлы-вложения;
- подписи к вложениям;
- статус публикации.

_Карточку можно опубликовать только в опубликованном разделе._

### Работа с файлами

Файлы прикрепляются к карточкам. Система сама определяет тип вложения по расширению файла: изображение, видео, аудио или документ.

При замене файла старый файл удаляется из хранилища. При удалении карточки удаляются ее главное изображение и все вложения.

## Секции и страницы приложения

### Публичные страницы

- `/` - главная страница DATUM Soft.
- `/projects` - список проектов.
- `/projects/:slug` - детальная страница проекта.
- `/login` - вход в систему.

### Защищенные страницы

- `/sections` - список разделов базы знаний.
- `/sections/create` - создание раздела.
- `/sections/:slug/edit` - редактирование раздела.
- `/sections/*` - просмотр раздела и его содержимого.
- `/sections/:slug/cards/create` - создание карточки в разделе.
- `/cards/:slug` - просмотр карточки.
- `/cards/:slug/edit` - редактирование карточки.
- `/projects/create` - создание проекта.
- `/projects/:slug/edit` - редактирование проекта.

### Основные сущности

- `Project` - публичный проект с описанием, изображением и геоданными.
- `Section` - раздел базы знаний, поддерживает вложенность.
- `Card` - карточка материала внутри раздела.
- `CardMedia` - файл-вложение карточки.
- `User` - пользователь системы.

## Какие файлы можно хранить

### Главное изображение проекта

Для проекта можно загрузить изображение. Оно хранится в каталоге `media/projects/main/`.

### Главное изображение карточки

Для карточки можно загрузить основное изображение. Оно хранится в каталоге `media/cards/main_images/`.

### Вложения карточек

Вложения карточек хранятся в каталоге `media/cards/attachments/<id карточки>/<тип файла>/`.

## Запуск через Docker

1. Скопируйте пример переменных окружения:

```bash
cp .env.docker.example .env.docker
```

2. Заполните значения в `.env.docker`:

```env
POSTGRES_DB=datum_db
POSTGRES_USER=<username>
POSTGRES_PASSWORD=<password>

SECRET_KEY=<django_secret_key>
DEBUG=False
ALLOWED_HOSTS=localhost,127.0.0.1,backend
CORS_ALLOWED_ORIGINS=http://localhost,http://127.0.0.1

VITE_API_BASE_URL=/api
VITE_MEDIA_BASE_URL=http://localhost/
```

3. Соберите и запустите контейнеры:

```bash
docker compose up --build
```

4. Приложение будет доступно по адресу:

```text
http://localhost/
```

PostgreSQL внутри Docker проброшен на порт `5433` хоста.

## Локальный запуск для разработки

### Backend

1. Перейдите в папку backend:

```bash
cd datum_backend
```

2. Установите зависимости:

```bash
pip install -r requirements.txt
```

3. Настройте переменные окружения в `datum_backend/.env`.

4. Примените миграции:

```bash
python manage.py migrate
```

5. Создайте администратора:

```bash
python manage.py createsuperuser
```

6. Запустите сервер:

```bash
python manage.py runserver
```

### Frontend

1. Перейдите в папку frontend:

```bash
cd datum_frontend
```

2. Установите зависимости:

```bash
npm install
```

3. Настройте переменные окружения в `datum_frontend/.env`.

4. Запустите dev-сервер:

```bash
npm run dev
```

5. Для production-сборки используйте:

```bash
npm run build
```

## API и документация

Основные API-маршруты:

- `POST /api/auth/login/` - получение JWT-токена.
- `POST /api/auth/refresh/` - обновление JWT-токена.
- `GET /api/auth/me/` - данные текущего пользователя.
- `/api/projects/` - список и создание проектов.
- `/api/projects/<slug>/` - просмотр проекта.
- `/api/projects/id/<id>/` - управление проектом.
- `/api/sections/` - список и создание разделов.
- `/api/sections/<slug>/` - просмотр раздела.
- `/api/sections/<slug>/content/` - содержимое раздела.
- `/api/sections/id/<id>/` - управление разделом.
- `/api/cards/` - список и создание карточек.
- `/api/cards/<slug>/` - просмотр карточки.
- `/api/cards/id/<id>/` - управление карточкой.
- `/api/cards/<card_id>/media/` - список и создание вложений карточки.
- `/api/media/allowed-extensions/` - список разрешенных расширений файлов.
- `/api/media/<id>/` - управление вложением.

Документация API доступна после запуска backend:

- Swagger UI: `/api/docs/swagger/`
- ReDoc: `/api/docs/redoc/`
- OpenAPI schema: `/api/schema/`

## Примечания по эксплуатации

- Папка `media/` содержит пользовательские загруженные файлы и должна сохраняться между перезапусками.
- В Docker для media и static используются отдельные volumes.
- При удалении карточки или проекта связанные изображения и вложения удаляются из файлового хранилища.
